Workbench

VS Code 配置

VS Code 是整套工作流的「工作台」：上半部分看文件，下半部分跑 AI。我们只需要完成三件事——下载、验证、装插件。

1.1在哪里下载 VS Code

打开官网

浏览器访问 code.visualstudio.com，网站会自动识别你的系统。

点击 Download 按钮并安装

Windows：双击下载好的 .exe 文件，一路下一步。关键一步：在「附加任务」页面务必勾选 添加到 PATH，其余保持默认。

macOS：下载后把图标拖进「应用程序」即可；也可以用命令行安装：

macOS
brew install --cask visual-studio-code
首次打开遇到安全提示

macOS 若提示「无法验证开发者」，进入 系统设置 → 隐私与安全性，点击「仍要打开」即可。

1.2如何确认已经安装好了 VS Code

方法一：直接打开应用（推荐，最可靠）

macOS：打开「启动台」，或在访达中进入 应用程序 文件夹，找到 Visual Studio Code 双击打开，能看到欢迎界面即安装成功。

Windows：在开始菜单搜索 Visual Studio Code，能正常启动即安装成功。

方法二：验证 code 命令行工具（可选，需先配置）

打开终端（macOS）或 PowerShell（Windows），输入：

Terminal / PowerShell
code --version

看到版本号，说明 code 命令已可用。注意：它验证的是命令行工具，不是应用本身——提示 command not found 并不代表 VS Code 安装失败，只说明这个命令还没配置。

macOS：先执行一次 Shell Command

在 VS Code 中按 Cmd+Shift+P 打开命令面板，搜索并执行 Shell Command: Install 'code' command in PATH；然后关闭终端重新打开，再运行 code --version。

Windows：检查 PATH

只有在安装时勾选了 添加到 PATH，并重新打开 PowerShell 后，code 命令才会生效；没勾选就重装一次并补勾。

本课程中怎么用

后续操作主要用 VS Code 界面打开文件夹，不强制要求 code 命令。把它配置好，以后在终端一键打开项目会更方便。

1.3如何配置 VS Code 插件

按 Cmd+Shift+X（Windows 为 Ctrl+Shift+X）打开插件面板。这里有一个必装插件——Opencode 插件，其余按需选择。

必装

装上它，AI 能看到你当前打开的文件和选中的代码，提问不用再复制粘贴；配合快捷键，写作、改代码时随叫随到。两种安装方式任选：

方式一：插件市场安装（推荐）

在插件面板搜索 OpenCode，找到官方插件，点击 Install。

方式二：在内置终端让它自动安装

按 Ctrl+` 打开 VS Code 内置终端，运行 opencode，插件会自动安装。前提是 code 命令已配置好（见 1.2 节 macOS 提示）。

The Agent

Opencode 配置

Opencode 是运行在终端里的 AI 助手，能读写本地文件、执行命令、联网查资料。装好它，你就有了一个能真正「动手干活」的 AI 搭档。

2.1在哪里下载 Opencode

官方下载页在 opencode.ai/download，终端版、桌面版、编辑器插件的入口都在这里。终端版有以下几种安装方式，任选其一即可，推荐最省事的官网一键脚本：

方法一：官网一键脚本（推荐，最简单）

一行命令完成安装，macOS / Linux / WSL 通用，不需要提前安装 Homebrew 或 Node.js：

macOS / Linux / WSL
curl -fsSL https://opencode.ai/install | bash
方法二：Homebrew（已装 Homebrew 的 macOS）
macOS
brew install anomalyco/tap/opencode
方法三：npm（Windows 常用，需先装 Node.js）

访问 nodejs.org，下载 LTS 版本的 .msi 安装包，安装时确保勾选 Add to PATH，然后：

Windows PowerShell
npm install -g opencode-ai

Windows 也可以换用包管理器：Scoop 用户执行 scoop install opencode，Chocolatey 用户执行 choco install opencode。

方法四：官网下载桌面版（可选）

不习惯命令行？到 opencode.ai/download 下载 OpenCode Desktop 安装包（macOS 的 dmg、Windows 的 exe，或执行 brew install --cask opencode-desktop）。

注意：桌面版是图形界面，本课程后续操作以终端版为准，建议仍按方法一安装。

验证安装
Terminal / PowerShell
opencode --version

看到版本号即安装成功。

Windows 常见报错

提示「禁止运行脚本」：执行 Set-ExecutionPolicy RemoteSigned -Scope CurrentUser，然后关闭并重开 PowerShell。

npm 下载超时：追加官方源重试 npm install -g opencode-ai --registry=https://registry.npmjs.org。

2.2如何配置 Opencode：先接通一个模型

第一次使用，先用免费模型把流程跑通。完整步骤如下：

创建工作目录并启动
Terminal / PowerShell
mkdir ~/opencode-lab
cd ~/opencode-lab
opencode

Windows 用户把 ~/opencode-lab 换成 $env:USERPROFILE\opencode-lab。

选择免费模型

在界面中输入 /models，在列表中找到标注 Free 的模型（如 GLM-5 Free、Big Pickle 等），回车确认。

测试连接

输入「你好，请简单介绍一下你自己」，能正常回复即配置完成。

第 3 节会做什么

免费模型响应偏慢、能力有限。下一节我们用 DeepSeek API 接入更稳定的模型，体验会明显提升。

Connect the Model

DeepSeek API 配置

API 是 AI 模型的「收费接口」。申请一个 DeepSeek 密钥，填进 Opencode，就能稳定使用更强的模型。整个过程分两步：拿密钥、填进 Opencode。

3.1如何获取 DeepSeek API

注册账号

访问 DeepSeek 开放平台 platform.deepseek.com，用手机号或邮箱完成注册并登录。

创建 API Key

进入控制台的 API Keys 页面，点击 Create new API key，起一个名字（例如 opencode-lab）后确认创建。

立即复制并保存密钥

密钥只显示一次，关闭页面后无法再看完整内容。先粘贴到备忘录保存好。

按需充值

API 按使用量计费。学生日常练习可以先充少量（如 10 元），用完后平台可随时再充。

3.2如何在 Opencode 中配置 DeepSeek API

启动并进入连接界面

在项目目录输入 opencode 启动，然后输入斜杠命令 /connect。

选择 DeepSeek 并粘贴密钥

在提供商列表里搜索并选择 DeepSeek，把你保存的 API 密钥粘贴进去，回车确认。

选择模型并测试

输入 /models，在列表中选择 DeepSeek 的模型（列表中会给出对话模型与推理模型，按实际显示选择），然后输入一个问题测试回复。

安全提醒：API 密钥等于钱包

不要把密钥发到群里、不要截图分享、不要上传到 GitHub。如果怀疑泄露，立刻到平台删除旧 Key 并重新创建。

04
Skills

Skill 基础

环境搭好后，真正的效率来自 Skill：把重复的解释固化成文件，让 AI 每次都按你的标准工作。这一节讲清楚三件事——是什么、怎么被唤醒、怎么写。

4.1什么是 Skill

Skill 是一组打包在文件夹中的指令，教会 AI 如何处理特定任务或工作流。核心文件是 SKILL.md，由 YAML 元数据和 Markdown 执行规则组成。

为什么需要它？回想你用 AI 的日常：临时写一段提示词完成一次性任务，完全够用。但当某类任务反复出现时，临时写法会暴露三个问题：

  • 要求漂移——今天要求先提炼要点再列行动项，明天只写「帮我总结一下」，结果每次都不一样；
  • 经验散落——好不容易试出的最佳格式，散落在历史对话里，下次还要重新解释；
  • 协作失准——你自己有手感，但同学、队友无法复现同样的结果。

Skill 解决的正是这三个问题：把做法提前写清楚，把散落在会话里的经验收成可复用的规则。

对比维度临时 prompt重复 promptSkill
复用性一次性，用完即弃手动复制粘贴系统自动匹配加载
一致性每次表述不同，结果波动取决于记不记得上次怎么写规则固定，结果稳定
协作性仅限个人靠口头传递文件化，团队共享
维护成本无需维护散落各处，难以更新集中维护，版本可控
判断标准

当某类任务反复出现，而且你总要重复解释做法时，就该考虑把它做成 Skill。

4.2如何唤醒一个 Skill

你不需要手动点名 Skill。系统用一套三阶段流程自动匹配：

阶段系统做什么读取的内容
发现启动时扫描所有可用 Skill只读 name 和 description，每个约 100 tokens
匹配根据你的请求判断相关性元数据对比
加载相关时才展开完整内容SKILL.md 正文、脚本、参考文档

这套机制叫渐进式披露：先暴露少量元数据，确认相关后再读正文，需要时才访问附加文件。所以安装 20 个 Skill，也只会先加载 20 份目录条目，再选择性展开 1–2 个。在 Opencode 中，已安装的 Skill 会出现在 AI 的 skill 工具清单里，AI 判断任务相关时才会调用并加载完整内容。

触发不良的两种信号

触发不足：该用的任务没反应——通常是 description 太模糊，缺少你实际会说的短语。

触发过度：无关任务也被触发——通常是 description 太宽泛，没有界定边界。

调试触发效果有个简单办法：直接问 AI——「你什么时候会使用这个 Skill？」如果它的回答和你的预期不一致，就去改 description。

4.3如何写一个 Skill

最小结构：一个文件夹 + 一个 SKILL.md

Skill 成立的最低要求只有一个文件：SKILL.md，由 YAML frontmatter（元数据）和 Markdown 正文（执行步骤）组成。文件夹名必须用短横线小写格式（kebab-case），例如 literature-reader；带空格、下划线或大写都不行。

目录结构
literature-reader/
├── SKILL.md          # 必需：触发条件 + 执行步骤
├── scripts/          # 可选：可执行脚本
├── references/       # 可选：参考文档
└── assets/           # 可选：模板与资源

在 Opencode 中，Skill 的存放位置分两级：

层级Opencode 路径作用域
个人级（全局）~/.config/opencode/skills/所有项目共享，适合通用工作流
项目级项目/.opencode/skills/仅当前项目可用，随项目一起分发
兼容目录

Opencode 还会自动扫描 Claude 兼容目录 .claude/skills/ 和 ~/.claude/skills/。从网上拿到的 Claude 格式 Skill，不改任何东西、直接放进自己的目录也能用。

frontmatter：两个必填字段

字段是否必填说明
name必填kebab-case 格式，1–64 个字符，与文件夹名一致
description必填说明「做什么、何时使用」，1–1024 字符
license / compatibility / metadata可选协议、环境依赖声明、作者版本等自定义信息

以上是 Opencode 能识别的字段，其他字段会被忽略。想限制某个 Skill 能不能被调用，可以在 opencode.json 里配置 permission.skill，属于进阶用法，先了解即可。

description 是最关键的字段，它决定系统能不能准确匹配。写作公式：做什么 + 何时使用 + 关键能力。

好的写法 vs 坏的写法
# 好：具体、包含触发短语、交代能力边界
description: >
  阅读经济学实证论文并生成结构化阅读笔记。当用户要求读文献、
  总结论文、做文献笔记时使用。覆盖研究问题、数据、方法、结论。

# 坏：太模糊，系统无法判断何时该用它
description: 帮助处理文档。

正文部分按步骤写清楚「怎么做」，把执行步骤、输出格式、约束条件一次交代完：

SKILL.md 最小示例
---
name: meeting-summary
description: >
  整理会议记录并生成结构化纪要。当用户要求总结会议、
  提炼行动项、生成会议纪要时使用。
---

# 会议纪要整理

## 执行步骤

### 第 1 步：识别会议信息
确认会议主题、参与人和时间。

### 第 2 步：提炼核心内容
提取关键结论、分歧点和待办事项。

### 第 3 步：结构化输出
按固定格式输出：会议主题、关键结论、行动项（含负责人和
截止日期）、待确认问题。

六条设计原则

原则含义反例
单一职责一个 Skill 只做一类事把摘要、改写、校对塞进同一个 Skill
描述可判别description 能让系统准确匹配写成一个「有用的写作 Skill」
正文可执行步骤足够具体，AI 能照做正文只写「请认真完成任务」
边界可说明清楚什么不属于这个 Skill把所有相关功能都往里塞
可组合多个 Skill 并存时不互相冲突两个 Skill 争抢同一类任务
可移植跨平台使用时行为一致依赖特定环境却不声明
常见误区

「Skill 越大越好」——错，边界模糊会让触发失真，保持单一职责。

「没有脚本就不算 Skill」——错，只有 SKILL.md 也能成立，脚本只是增强层。

「description 越宽泛越好」——错，越宽泛系统越难匹配，要写清具体场景。

4.4如何获取别人的 Skill

  • 官方示例仓库：Anthropic 的 github.com/anthropics/skills，提供多个可直接使用或定制的 Skill；这种 Claude 格式与 Opencode 兼容，下载后放进自己的 skills 目录即可。
  • 教材配套扩展包：本课程配套 15 个实用 Skill（Word 处理、PDF 操作、幻灯片制作、网页抓取、arxiv 检索等），仓库地址 github.com/Xueheng-Li/ai-tools-installation，安装指令见下方。
  • 技能市场：开源社区的 ClawHub（clawhub.ai）托管了大量 AgentSkills 格式的技能，Opencode 同样能识别，下载后放入自己的 skills 目录即可。

   ~/.config/opencode/skills/（目录不存在就先创建）
3. 完成后删除临时目录

装好后列出 ~/.config/opencode/skills/ 下的所有子文件夹确认。
别人的 Skill 先读再用

第三方 Skill 任何人都能发布，存在投毒风险。安装前做三项自查：看下载量、看仓库活跃度、看作者背景；装好后先打开 SKILL.md 读一遍再使用。

05
Hands-on

练习：定制自己的文献阅读 Skill

目标：从零做出一个能自动触发的文献阅读 Skill，实现四个功能。做完这个练习，你就掌握了 Skill 的完整工作流。

功能 1
抓取文献基本信息
从 PDF 或 Markdown 中提取标题、作者、期刊、年份、摘要与研究问题。
功能 2
整理成固定格式
按你偏好的结构输出笔记：数据样本、识别策略、主要结论、贡献与局限。
功能 3
多维度比较
一次提供多篇文献时，自动生成对比表，横向比较问题、方法、数据与结论。
功能 4
给出研究建议
指出文献尚未回答的问题，提出可拓展的研究方向。

5.1操作步骤

创建 Skill 文件夹

在你的项目目录下执行，创建项目级 Skill 目录：

Terminal
mkdir -p .opencode/skills/literature-reader
新建 SKILL.md，粘贴下方完整示例

文件路径为 .opencode/skills/literature-reader/SKILL.md。可以直接复制本页 5.3 的示例，也可以按自己的阅读习惯修改格式。

准备一篇论文做测试

下载 1–2 篇经济学论文（中文或英文均可），放在项目目录下。

启动并测试触发

在项目目录启动 opencode，输入：

输入框
帮我读一下 paper.pdf，按文献笔记的格式整理

不需要提到 Skill 的名字。只要请求和 description 匹配，系统会自动加载并执行。

迭代修改

对输出不满意，就直接改 SKILL.md 里的格式要求（比如加上「标注关键系数」「增加数据来源一行」），每改一次重新测试一次。改完后输入 /new 新开对话，确保加载的是新版。

验证触发效果

直接问 AI：「你什么时候会使用 literature-reader 这个 Skill？」如果回答与预期不符，回到 description 补触发短语。

5.2验收清单

  • 输入「帮我读这篇文献」，AI 自动按固定格式输出了笔记。
  • 一次提供两篇文献时，能生成横向对比表。
  • 笔记中的数字和结论都能在原文中找到，没有编造。
  • 说「根据这些文献提研究建议」时，能指出研究空白并给出方向。

# 文献阅读助手

## 第 1 步：抓取基本信息

从用户提供的 PDF 或 Markdown 中提取：

- 标题、作者、发表期刊、年份
- 摘要与关键词
- 一句话研究问题

## 第 2 步：生成结构化笔记

按以下固定格式输出：

- 一句话总结
- 研究问题
- 数据与样本（来源、时间跨度、处理方式）
- 识别策略与计量方法
- 主要结论（含关键系数）
- 贡献与局限

## 第 3 步：多篇文献对比

当用户提供多篇文献时，生成对比表：

| 维度 | 文献 A | 文献 B |
|---|---|---|
| 研究问题 | | |
| 数据与样本 | | |
| 识别策略 | | |
| 主要结论 | | |
| 创新点 | | |

## 第 4 步：研究建议

- 指出各文献尚未回答的问题
- 给出 2-3 个可拓展的研究方向，说明为什么值得做

## 约束

- 所有信息必须来自文献本身，不得编造数据或结论
- 文献未提及的信息标注“未提及”
- 只做学术梳理，不评价作者水平

先把 SKILL.md 写好、跑通，再考虑加入脚本和模板。Skill 的质量不取决于文件夹多丰富，而取决于触发是否明确、步骤是否稳定。
